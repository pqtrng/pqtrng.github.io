WM-811K Wafer Defect Detection Pipeline
SemiconductorData EngComplete
A DE-first MLOps pipeline classifying wafer-map defect patterns from WM-811K, structured around the CRISP-ML(Q) lifecycle. Medallion (Bronze/Silver/Gold) Parquet data layer with Pandera validation and pytest + GitHub Actions CI; reproducible preprocessing (stratified 70/15/15, nearest-neighbor 64×64 resize preserving discrete die values); ResNet-18 with a CIFAR-style stem, trained from scratch, plus domain-safe augmentation (90° rotations / flips only — pixel-permutation-safe). Served via FastAPI + Docker: /predict with optional Grad-CAM heatmap, request validation reusing the same wafer-grid gate as the data pipeline ("one rule set, two doors"), and the promoted checkpoint pulled from a GitHub Release with SHA-256 verification at build time — the MLflow registry stays host-side as the manual promotion gate. Evaluated with macro-F1 + per-class metrics on a natural-distribution test set — accuracy would be misleading here.
macro-F1 0.828 (baseline CNN) → 0.880 (ResNet-18 scratch) → 0.920 (+ domain-safe aug)Accuracy 0.942 · CLI retrain reproduces the notebook within ±0.01 (0.915 vs 0.920)

CPS Anomaly Detection Pipeline
SemiconductorSecurityComplete
A DE-first anomaly-detection pipeline on the HAI industrial control-system testbed, built so the evaluation is as defensible as the model. Medallion Bronze → Silver → Gold with Pandera validation and SHA-1 fingerprinting; the feature scaler is fit on train-normal only and the detection threshold on a held-out calibration split, applied unchanged to holdout — the leakage boundary is the design, not an afterthought. An LSTM-autoencoder over 60-step windows is benchmarked against a z-score baseline that turns out to be genuinely hard to beat. Raw window-level metrics are the headline and point-adjust is reported only beside them with its inflation spelled out, because PA-only recall overstates every detector by 20–25 points. Detection latency is framed as an SLI against a 30-second SLO. Targets the PLC/SCADA layer that SEMI E187 deliberately leaves out of scope, aligned instead with IEC 62443 for OT monitoring. Batch-first by design — no streaming or real-time claim is made.

CircuitNet Routing-Congestion Prediction
SemiconductorMLAudited · v1
Predicting global-routing congestion from placement-stage feature maps on CircuitNet-N14, with a U-Net over 128×128 patches. The contribution is the data rigor: SHA-1 fingerprinting at the Silver layer showed 60% of the dataset is bit-identical duplicates — PnR sweep parameters appear in filenames but do not alter the feature maps — so the honest sample count is 4,216, not 10,606, and no duplicate group crosses a design boundary, which keeps the design-wise split leak-free. Chips are cropped at native resolution rather than resized, because congestion is a density on a physical routing grid and rescaling would confound domain shift with resolution loss. Figures at audit markers in the decision document are inserted from committed probe artefacts by a rendering step; the prose around them is hand-written and gated by a test whose baseline of unverified quantities must stay empty — every error the audit found lived in that hand-written layer, and the git history shows the baseline shrinking as they were closed.
Headline finding — the checkpoint-selection rule decides the result. In unet_a the lowest-error and highest-F1 epochs land 36 epochs apart and differ 15.9× in hotspot F1 (0.0022 → 0.0356 — low in absolute terms; the result is the shape of the disagreement, not the height of the bars); across five recorded runs the two rules never agree — 1.5×–44.3× over four of them, with the fifth unbounded (its error-selected epoch scored F1 = 0).Why pixel metrics lie here — on the training split ground truth is 1.601% non-zero (val 0.955%, test 5.575%), so where the target is sparsest an all-zero predictor scores near-perfectly while detecting zero hotspots — a function of sparsity, not a constant of the task. Every error figure is reported as a ratio to its own split's baseline.Reproducibility — full test suite passing from a clean clone with no dataset required; CI green (ruff + pytest), pre-commit and pre-push run the same checks; weights published as release model-v1 with digests verifiable via sha256sum -c SHA256SUMS.
